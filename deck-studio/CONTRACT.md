# deck-studio · kit contract (wave 1, 2026-10-08)

A web deck: one Vite app, one URL, keys and clicks, a presenter window, a PDF export. Slides are React components
built from the kit; the runtime is attribute-driven like the landing-studio engine (same token names, same
`html.js` / `html.rm` gating, same failsafe idea), but step-driven instead of scroll-driven.

## App layout (made by `kit/app-template` + `kit/app-template/sync-kit.sh`)
```
index.html                    inline boot script in <head> (adds html.js, html.rm), <div id="root">
src/main.tsx                  mounts <Deck slides={DECK} />
src/deck.tsx                  THE ORDER: export const DECK: SlideDef[] = [{ id, type, data, notes?, transition? }]
src/kit/runtime/deck.ts       navigation state, steps, hash, keys, zoom, fullscreen, presenter channel, media hooks
src/kit/react/{Deck,Slide,Step,SplitWords,Hud,Presenter}.tsx
src/styles/tokens.css (app-owned after first copy)   src/styles/deck.css (kit-owned, re-synced)
src/slides/<type>/<Type>.tsx, <type>.css, data.example.ts, preview.tsx      slide.md stays in the skill
src/preview-deck.tsx          generated by sync-kit from every data.example (`?preview` one slide per type,
                              `?preview=<type>` the `variants` that type's preview.tsx exports)
src/slides/registry.ts        generated by sync-kit: the type -> component map
public/                       images, videos, pdfs the slides reference, qr.svg
```
Imports: `@/kit/react/Slide`, `@/kit/react/Step`, `@/kit/react/SplitWords`, `@/slides/<type>/<Type>`.

## Stage
- Design box **1920 x 1080**, every size in px at that box; the runtime scales `.deck-stage` with
  `transform: scale(min(vw / 1920, vh / 1080))`, centred, letterboxed on `--bg`. Nothing else responds to the viewport.
- One slide visible at a time: `<section class="slide" data-slide="<id>" data-steps="N">`; `.is-current` on the
  visible one; the previous keeps `.is-leaving` for the transition length, the rest are `display: none`.
- Slide backgrounds (glows, images) live inside the slide, full stage; the stage itself paints `--bg`.
- Transitions between slides: `data-transition="fade" | "none" | "wipe"` on the slide (default fade: 320 ms opacity
  plus 12 px rise, exits at 60%). The deck-level default comes from `<Deck transition>`.

## Steps (fragments)
- `data-steps` is the highest `at` on the slide (0 = everything visible at once); `at={0}` enters with the slide.
  The runtime holds `step` in 0..N.
- `<Step at={k}>` renders `[data-step="k"]`; the runtime sets `.in` on every `[data-step]` whose `k <= step`.
  Steps may also carry `data-rv` variants from landing-studio (`""` rise, `mask`, `pop`, `side`, `wipe`, `blur`) and
  `--i` for ladders inside one step (max 6, `--stagger` 70 ms). Hidden states are gated `html.js:not(.rm)`.
- Space is reserved: a hidden step keeps its layout box (opacity and transform only), so nothing on the slide moves
  when a step enters. swap groups are the one exception: `<Step swap="g">` members inside a `.deck-swap` container replace each
  other in place (used by screenshot-zoom and two-up).
- Going back one step removes `.in` (exit at 60% of the entrance). Going back from step 0 goes to the previous
  slide at its last step.
- Reduced motion (`html.rm`, also forced with `?rm`): no transitions, steps still gate visibility (a presenter needs
  them), slide switches are instant. No JS: all slides stacked vertically, every step visible, a readable document;
  a Vite app renders nothing without JS, so `npm run build` runs `vite build` then `src/kit/runtime/prerender.mjs`,
  which writes the slides into `dist/index.html`.
- Failsafe: if the runtime has not mounted (no `html.deck-ready`) within 3.5 s, `html.js` is swapped for
  `html.deck-static` by the boot script: the stacked document.

## Navigation
- Next: `ArrowRight` `Space` `Enter` `PageDown` click on the stage. Previous: `ArrowLeft` `PageUp` `Backspace`.
  `Home` / `End` first / last slide (at step 0). Digits then `Enter` jump to a slide number. `F` fullscreen. `H` hide the hud.
  `P` opens the presenter window. `+` `-` `0` zoom the stage. `?` shows the key list.
- URL hash: `#<slide>` (1-based) and `#<slide>.<step>`; written on every move with `history.replaceState`, read on load.
- Clicks inside `<a>`, `<button>`, `<input>`, `<iframe>`, `<video controls>`, `[data-no-nav]` do not navigate.
- The hud (bottom right, mono): `slide / total`, a thin progress bar; hidden with `H`, hidden in `?print`.

## Presenter
- `?presenter` opens the presenter view: current slide (scaled), next slide, this slide's `notes` (markdown-ish
  lines), elapsed timer (starts on first navigation, `T` resets), step `k / N`.
- Sync over `BroadcastChannel("deck:<id>")` where `<id>` comes from `<Deck id>`: both windows move together, either
  can drive. Falls back to localStorage events if BroadcastChannel is missing.

## Media and demos
- `<video>` in a slide: `muted playsInline preload="metadata"` with a `poster`; the runtime plays it on slide enter
  (or on the step it belongs to) and pauses on leave. Sound only via a visible control.
- `demo` slides embed an `<iframe>` (`data-no-nav`) with a fallback screenshot shown until the iframe loads and
  always in `?print`. The URL is a prop, never hardcoded.
- Images: explicit `width` and `height`, local files in `public/`, never hotlinked.

## Print and export
- `?print`: every slide stacked, each a 1920 x 1080 page, every step in, hud hidden, no transitions, videos as posters,
  iframes as fallbacks. `scripts/export.cjs` loads it with playwright and writes `deck.pdf` (page size 1920 x 1080 px)
  plus `slides/<nn>.png`.

## Tokens (`src/styles/tokens.css`)
- Brand: `--bg --ink --ink-2 --muted --accent --accent-2 --line --font-sans --font-mono` (same names as landing-studio).
- Deck: `--slide-pad: 112px`, `--t-step: .45s`, `--t-slide: .32s`, `--stagger: 70ms`,
  `--ease: cubic-bezier(.16,1,.3,1)`, `--spring: cubic-bezier(.32,1.28,.36,1)`, `--inout: cubic-bezier(.65,0,.35,1)`,
  `--failsafe: 3.5s`.
- Type scale at 1920: kicker 26px mono, display 124px (title slide, `--fs-display`), title 88px/1.02, h2 64px,
  body 36px/1.35, caption 24px, big number 320px. `<html lang>` comes from `VITE_DECK_LANG` in `.env`.

## Slide types (`kit/slides/<type>/`, classes prefixed `.<type>-`)
Each folder: `slide.md` (what, props, steps, notes slots), `<Type>.tsx`, `<type>.css`, `data.example.ts` (Romanian,
diacritics, labelled "Exemplu", no invented facts; exports `example` and `notes`), `preview.tsx` (exports `variants`). A slide component receives `{ data, step }` and
renders inside `<Slide>`; it declares its step count via `export const steps = (data) => number`.

## House rules every file obeys
No em dashes anywhere; transforms, opacity and clip-path only; nothing moves when a step enters (space reserved);
every number and name on a slide maps to a facts.md line; third-party logos never recoloured; no new scroll or
resize listeners outside the runtime; no GSAP, no reveal libraries.

## Known behaviours (wave 1)
- Step CSS keys off `.in`, never off the `step` prop (the presenter's next-slide pane relies on it).
- Every open window with the same deck id joins the sync; a stale tab can pull the presenter to its slide. Close old tabs.
- `sync-kit.sh` runs under macOS bash 3.2.
